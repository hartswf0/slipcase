ZETTEL

ID:
FUTAMURA-001

TITLE:
Compilation can be obtained by freezing the source program inside its interpreter.

SOURCE:
Neil D. Jones, Carsten K. Gomard, and Peter Sestoft — Partial Evaluation and Automatic Program Generation — 1993 — §1.5.1 and §4.3.2–4.3.3; following Yoshihiko Futamura’s 1971 result.

PASSAGE:
[PARAPHRASE]
Specializing an interpreter with respect to one fixed source program produces a target program implementing that source program. The authors characterize the result as compilation by partial evaluation and describe the target as a specialized interpreter.

RESEARCH OBJECT:
COMPILER and INTERPRETER cease to be fundamentally different mechanisms.

Compilation emerges by staging interpretation.

LOCAL MOVE:
The parent asked what distinguishes program from input.

Futamura makes the source program simultaneously:

INPUT TO THE INTERPRETER

and:

STATIC MATERIAL FROM WHICH TARGET CODE IS GENERATED.

SOURCE TERMS:
interpreter
source program
target program
specialization
first Futamura projection
compilation

WHAT BECAME STRANGE:
The target program contains pieces of the interpreter specialized by information extracted from the source program.

Neither SOURCE PROGRAM nor INTERPRETER alone survives unchanged as the executable artifact.

QUESTION:
Is compiled code best understood as a program translation or as an interpreter partially evaluated into its input?

DEEPER QUESTION:
If interpreter machinery can disappear into residual code, where should the boundary between semantics and program representation be located?

MECHANISM:
interpreter int
+
source program source
→ specializer mix
→ target

such that:

target(input)

produces the same result as:

int(source,input).

FORMAL SHIFT:
<INTERPRETER + PROGRAM-AS-INPUT>
→ [SPECIALIZATION]
→ <TARGET PROGRAM>

SOURCE FORMALISM:
The source gives the first Futamura projection:

    target = [[mix]] [int, source]

and establishes its behavior through the interpreter and specialization equations.

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]

Before specialization:

    I(source,x)

After specialization:

    I_source(x)

where:

    I_source = Specialize(I,source).

Thus compiled programhood can be seen as:

    INTERPRETER RESIDUALIZED WITH RESPECT TO SOURCE.

TENSION:
A hand-written compiler need not literally be generated by specialization, so this is an existence/construction result rather than the only ontology of compilation.

MISSING:
Which semantic distinctions between:
INTERPRETER,
COMPILER,
and
TARGET PROGRAM

survive all semantics-preserving staging transformations?

BOUNDARY:
Interpreter and compiler are operational roles that can be transformed into one another under suitable program-specialization machinery.

CITATION TRAIL:
[[UPTAKE-003]]

TEST:
Implement a tiny interpreter and specialize it to one source program.

Compare the generated target with:
the source syntax,
the interpreter syntax,
and a hand-written compiled target.

Measure where each piece of operational machinery came from.
