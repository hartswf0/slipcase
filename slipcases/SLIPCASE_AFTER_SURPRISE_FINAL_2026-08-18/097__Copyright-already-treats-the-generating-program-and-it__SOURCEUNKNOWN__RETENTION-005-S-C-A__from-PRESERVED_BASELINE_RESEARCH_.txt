ZETTEL

ID:
RETENTION-005-S-C-A

TITLE:
Copyright already treats the generating program and its audiovisual outputs as separable works, blocking automatic inheritance in either direction.

SOURCE:
Williams Electronics, Inc. v. Artic International, Inc. — 685 F.2d 870 (3d Cir. 1982); Apple Computer, Inc. v. Franklin Computer Corp. — 714 F.2d 1240 (3d Cir. 1983).

PASSAGE:
[PARAPHRASE]
Early software cases distinguish copyright in a computer program from copyright in audiovisual displays it generates; causation does not merge them into one work.

RESEARCH OBJECT:
GENERATOR AND OUTPUT HAVE SEPARATE COPYRIGHT ONTOLOGIES.

LOCAL MOVE:
The law already contains a structural separation between generator and output.

SOURCE TERMS:
computer program
audiovisual work
display
object code
expression
output

WHAT BECAME STRANGE:
PROGRAM→DISPLAY can support independent rights in both objects.

QUESTION:
Could a human-authored prompt or generative rule be protected while a resulting output remains only partly or not at all human-authored?

DEEPER QUESTION:
What relation, if any, should propagate authorship from an upstream expressive work into a distinct downstream work produced through its operation?

MECHANISM:
copyrightable P → machine execution → display/output Y; Y requires separate analysis.

FORMAL SHIFT:
<UPSTREAM AUTHORSHIP> ↛ <DOWNSTREAM AUTHORSHIP>

SOURCE FORMALISM:
Cases distinguish literary-work protection for program from audiovisual-work protection for displays.

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]
Copyrightable(P) and Copyrightable(Y) are independent; Author_h(P) does not entail Author_h(Y).

TENSION:
A downstream work can incorporate protected upstream expression, raising derivative/substantial-similarity issues.

MISSING:
Doctrine for probabilistic rather than deterministic constraint propagation.

BOUNDARY:
Causal generation alone does not establish legal identity or common authorship.

CITATION TRAIL:
[[RETENTION-005-S-C]] → generator/output inheritance → Williams/Apple → separate work objects.

TEST:
Analyze prompt, workflow/program, model customization, and final output as four potentially distinct works before relating them.
