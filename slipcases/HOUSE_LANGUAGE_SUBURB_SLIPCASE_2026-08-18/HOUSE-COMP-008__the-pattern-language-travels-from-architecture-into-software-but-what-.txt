HOUSE-COMP-008

TITLE:
THE “PATTERN LANGUAGE” TRAVELS FROM ARCHITECTURE INTO SOFTWARE, BUT WHAT TRAVELS IS REUSABLE DESIGN KNOWLEDGE RATHER THAN EXECUTABLE SYNTAX.

SOURCE:
Kent Beck and Ward Cunningham — “Using Pattern Languages for Object-Oriented Programs” — 1987 — OOPSLA-87 Workshop on Specification and Design for Object-Oriented Programming.

PASSAGE:
[QUOTE]
“We outline our adaptation of Pattern Language to object-oriented programming.”

RESEARCH OBJECT:
THE ARCHITECTURE → SOFTWARE MIGRATION OF “LANGUAGE.”

LOCAL MOVE:
Beck and Cunningham explicitly adapt Alexander’s pattern-language idea to object-oriented program design; patterns become a way of recording and communicating recurrent structures.

SOURCE TERMS:
pattern language; object-oriented programming; design; patterns; adaptation

WHAT BECAME STRANGE:
The traffic does not run only COMPUTING → ARCHITECTURE. Architecture supplies a design vocabulary that becomes important in software engineering.

QUESTION:
What exactly crossed disciplines when Alexander’s architectural language became a software pattern language?

DEEPER QUESTION:
Did software inherit Alexander’s generativity, communication of tacit practice, decomposition of design problems, or merely the word PATTERN?

MECHANISM:
Recurring design experience is abstracted into named reusable patterns that help practitioners recognize and resolve recurring situations.

FORMAL SHIFT:
<ARCHITECTURAL DESIGN KNOWLEDGE>
→ <PATTERN>
→ [ADAPT DOMAIN]
→ <SOFTWARE DESIGN KNOWLEDGE>

SOURCE FORMALISM:
A collection of interconnected design patterns, not programming-language syntax and not automatically executable code.

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]
ARCHITECTURE → DESIGN PATTERNS → SOFTWARE DESIGN → SOFTWARE INFRASTRUCTURE → COMPUTATIONAL ARCHITECTURE. This is conceptual circulation, not a demonstrated causal lineage for every later system.

TENSION:
The migration can be narrated too neatly; shared vocabulary is not proof of downstream influence.

MISSING:
Which later CAD, BIM, generative-design, or architectural-software systems explicitly cite software patterns?

BOUNDARY:
Beck and Cunningham explicitly adapt pattern-language ideas to object-oriented software; they do not turn patterns into formal semantics.

CITATION TRAIL:
Christopher Alexander; Beck/Cunningham; Gamma et al.; Pattern Languages of Programs; architectural software influenced by patterns.

TEST:
Trace ALEXANDER 1977 → BECK/CUNNINGHAM 1987 → SOFTWARE PATTERN LITERATURE → ARCHITECTURAL COMPUTATION and require an explicit receipt at every edge.
