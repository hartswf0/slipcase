ZETTEL

ID:
INGOLD-PROMPT-008

TITLE:
“THE PROMPT IS NOT THE PROGRAM” BECOMES STRONGER IF PROGRAMMING IS LOCATED IN THE INTERLEAVING OF DESCRIPTION AND EXECUTION RATHER THAN IN EITHER ONE ALONE.

SOURCE:
Tim Ingold — Making: Anthropology, Archaeology, Art and Architecture — 2013 — Chapter 4, “On Building a House,” pp. 55–56.

PASSAGE:
[QUOTE]
“their designing, like their drawing, was a process of work, not a project of the mind”

[PARAPHRASE]
Ingold argues that medieval builders need not be understood as first completing a design and then executing it. Drawing, designing and material construction could remain interleaved within ongoing work itself.

RESEARCH OBJECT:
PROGRAMMING DURING EXECUTION.

LOCAL MOVE:
Ingold dismantles DESIGN THEN BUILD. This is close to the paper’s SPECIFY THEN EXECUTE becoming SPECIFY → EXECUTE → SPECIFY → EXECUTE. Novelty may lie not in natural language as medium but in return of specification to the temporal interior of making.

SOURCE TERMS:
design; drawing; building; work; craft; process; taking care; construction

WHAT BECAME STRANGE:
The paper describes LLM programming as a shift in time. Ingold provides a historical counterexample to treating specification-before-execution as the default temporal structure of skilled production. Conventional programming may be unusual in trying to move so much determination before execution.

QUESTION:
Is deferred formalization a genuinely new unit of programming, or the computational recovery of an older unit of making in which conception and execution were never fully separated?

DEEPER QUESTION:
What features of classical programming made pre-specification unusually valuable, and what features of generative models make interleaving specification and execution viable again?

MECHANISM:
A partial representation guides an operation; operation changes situation; changed situation generates new design information; representation is revised from within the process.

FORMAL SHIFT:
<PROGRAM FIRST / EXECUTION SECOND>
→ <PARTIAL DESCRIPTION + EARLY EXECUTION>
→ [OBSERVE / REDESIGN / CONTINUE]
→ <PROGRAM EMERGING WITH ITS EXECUTION>

SOURCE FORMALISM:
NONE

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]
CLASSICAL IDEAL: SPECIFY ──────────── EXECUTE.
DEFERRED FORMALIZATION: SPECIFY₀ → EXECUTE₀ → SPECIFY₁ → EXECUTE₁ → SPECIFY₂ → ... .
INGOLDIAN MAKING: DESIGN₀ ⇄ WORK₀ ⇄ DESIGN₁ ⇄ WORK₁ ⇄ ... . Structural resemblance is strong; genealogy is unproven.

TENSION:
Calling deferred formalization “new” risks conflating NEW TO PROGRAMMING INTERFACES with NEW AS A FORM OF MAKING. Ingold pressures the second claim. Novelty may lie in executable artifacts participating in older iterative temporality at extremely low cost.

MISSING:
A historical comparison among craft production, interactive programming, REPLs, debugging, live coding, programming by demonstration, CAD iteration, LLM prompting. Novelty must be split among LOOP, SPEED, ACCESSIBILITY, and SEMANTIC LATITUDE.

BOUNDARY:
Ingold provides no genealogy from medieval construction to generative programming. Formal resemblance is not historical influence.

CITATION TRAIL:
[[THE PROMPT IS NOT THE PROGRAM]] → Ingold — “On Building a House” → David Turnbull → Lucy Suchman → Donald Schön → interactive programming → REPL history → live coding → programming by demonstration → LLM natural-language programming.

TEST:
Historicize the loop. For each candidate practice record PARTIAL SPECIFICATION, EARLY EXECUTION, VISIBLE ARTIFACT, REVISION FROM OUTPUT, PRESERVATION OF PRIOR CONSTRAINTS, CHEAP REGENERATION, SEMANTICALLY LOOSE INPUT. Whatever remains after subtraction is the genuinely new property.
