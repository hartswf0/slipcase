TITLE:
The child schema hides inquiry provenance inside intellectual relations

SOURCE:
User-provided prompt system — PRIME ZETTEL FORAGE — RECURSIVE INQUIRY v3.1 — supplied 2026-08-18.

PASSAGE:
[PARAPHRASE] The prompt forbids PARENT and PROVENANCE fields. Parentage is instead encoded through LINKS and, when useful, CITATION TRAIL, while SOURCE remains reserved for evidentiary provenance.

RESEARCH OBJECT:
The design deliberately reuses intellectual-link fields to encode process lineage.

LOCAL MOVE:
It avoids contaminating the invariant schema with orchestration metadata.

SOURCE TERMS:
LINKS
CITATION TRAIL
SOURCE
provenance of the evidence
provenance of the inquiry

WHAT BECAME STRANGE:
A link can now mean both “this idea is intellectually related to that idea” and “this object was generated from that object.”

QUESTION:
Can research lineage remain reconstructable when generative ancestry and conceptual relation occupy the same field?

DEEPER QUESTION:
At what point does preserving a clean recursive datatype make the graph itself less semantically typed?

MECHANISM:
Generation event:
parent → child

is serialized as:
child.LINKS += parent_ID

rather than as an explicitly typed PARENT_OF / GENERATED_BY relation.

FORMAL SHIFT:
<generation event>
→ <ordinary link entry>
→ [infer ancestry from convention]
→ <recursive compatibility>

SOURCE FORMALISM:
LINKS:
  include [[PARENT-ZETTEL-ID]]

CITATION TRAIL:
  [[PARENT-ZETTEL-ID]]
  → source followed
  → new research object

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]

LINKS_TO(x,y) ≠ GENERATED_BY(x,y)

Encoding both as the same literal relation creates a later inference requirement.

TENSION:
Ancient Master later distinguishes native LINKS_TO from derived GENERATED_BY, revealing that the semantic distinction excluded from the zettel has to reappear in compiler state.

MISSING:
A lossless rule for distinguishing an ordinary intellectual link to a parent from a lineage link to that same parent.

BOUNDARY:
If every parent link is mechanically registered at generation time outside the payload, the ambiguity can be resolved. The v3.1 prompt itself does not specify such an external registry.

TEST:
Construct three cases:
1. child generated by A but intellectually unrelated;
2. child intellectually links to A but was not generated by it;
3. both.
Determine whether the exact preserved zettel payload alone can distinguish all three.
