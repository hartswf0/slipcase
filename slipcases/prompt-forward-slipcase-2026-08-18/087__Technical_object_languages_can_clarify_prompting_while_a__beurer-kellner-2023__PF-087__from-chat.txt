TITLE:
Technical object languages can clarify prompting while also biasing governance toward what engineers can formalize.

SOURCE:
Beurer-Kellner, Fischer, and Vechev — Prompting Is Programming — 2023.

PASSAGE:
[PARAPHRASE] LMQL makes model-facing operations explicit through a programming language combining prompts, constraints, and control flow.

RESEARCH OBJECT:
An object language renders some forms of prompting beautifully while excluding others.

LOCAL MOVE:
The source demonstrates the power of formalization.

SOURCE TERMS:
query language; constraints; control flow; programming.

WHAT BECAME STRANGE:
“Give governance an object language” immediately raises the question of whose object language.

QUESTION:
Would an LMQL/DSPy-style ontology systematically privilege technical prompt work over literary, design, conversational, or tacit prompting?

DEEPER QUESTION:
Can an operational ontology remain plural?

TENSION:
Without formalization, distinctions remain vague; with it, the ontology may narrow the field.

MISSING:
Comparative representations from nontechnical prompt practices.

BOUNDARY:
LMQL is a programming language, not a universal grammar of prompting.

CITATION TRAIL:
Design methods; literary prompting; multimodal interaction.

TEST:
Attempt to represent five radically different prompting practices in one technical ontology and catalogue what cannot be expressed.
