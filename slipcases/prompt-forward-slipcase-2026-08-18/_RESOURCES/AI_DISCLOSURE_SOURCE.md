## The pharmakon is not merely AI

I think your *pharmakon* formulation gets much stronger if we locate the ambiguity specifically in **operational language**.

A prompt can be:

**cure:** a capability-producing intervention.

or

**poison:** evidence that an external intelligence contaminated the work.

The prompt itself has not changed.

What changes is the **institutional frame in which its causal power is interpreted**.

In engineering, causal power is exactly what gives the prompt value:

> Can you get the model to do something useful that it could not reliably do before?

In research-integrity discourse, causal power can become precisely what makes the prompt suspicious:

> Did the AI substantively influence something important?

So the same facts can produce opposite evaluations:

**It changed the result substantially.**

Engineering:

> **Excellent.**

Compliance:

> **Potentially problematic. How was this disclosed?**

**It had significant effect.**

Engineering:

> **This is a contribution.**

Compliance:

> **This may cross the disclosure threshold.**

**Nobody else could reliably get this behavior, but your prompting/harness can.**

Engineering:

> **Novel capability.**

Compliance:

> **Greater AI involvement.**

That is a genuine *pharmakon*.

And in the Guidance, the explicit positive ontology is no richer. Prompts appear principally as potential adversarial inputs and jailbreak/injection risks.

That yields this bizarre table:

| Context What the prompt becomes  |                                     |
| -------------------------------- | ----------------------------------- |
| AI engineering                   | engineered behavioral specification |
| Agent architecture               | operational component               |
| Product development              | source of capability                |
| Employment                       | evidence of skill                   |
| Startup                          | potential IP / moat                 |
| Technical research               | experimental method / architecture  |
| GT scholarly guidance            | largely undefined                   |
| GT security guidance             | injection vector                    |
| Disclosure review                | evidence of AI involvement          |
| Misconduct inquiry               | potential evidentiary record        |

The problem isn't simply “academia doesn't appreciate prompts.”

**Technical academia plainly does.**

The more precise problem is that **academic AI governance has failed to import the ontology of the thing that technical AI research is actually building.**

The GT disclosure language is a **metalanguage for policing contribution**.

It contains predicates like:

**substantive**
 **magnitude**
 **significance**
 **appropriate**

But it lacks an object-language theory of the underlying activity:

**What is prompting?**

**What is prompt engineering?**

**What is a good prompt?**

**When is a prompt an instrument?**

**When is a prompt itself a scholarly contribution?**

**When is a loop a method?**

**When is selection intellectual work?**

**When is orchestration authorship?**

**When does a prompt create a capability?**

Without answering these, the policy is trying to classify the magnitude of something it has never actually defined.

That is a remarkable inversion.

---

And I think the *pharmakon* formulation can be compressed into something quite powerful:

> **AI governance recognizes the prompt principally when it needs to assign liability; AI engineering recognizes the prompt when it needs to assign capability.**

Or even more sharply:

> **In the laboratory, the prompt can be an invention. In the misconduct file, the same prompt can be evidence. In the scholarly record, somehow, it becomes nothing.**

That “nothing” is where I think your research question lives.

Not:

> **Should prompts be disclosed?**

But:

> **What kind of scholarly object is an instruction that changes what a generative machine can do?**
