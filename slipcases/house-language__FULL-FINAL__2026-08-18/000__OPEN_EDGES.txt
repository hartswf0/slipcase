OPEN EDGES

HOUSE-COMP-000 — QUESTION
At what point does a verbal description cease to be merely upstream of construction and become part of an executable construction system?

HOUSE-COMP-000 — MISSING
Building codes; structural reasoning; tolerance; procurement; construction sequencing; site uncertainty; robotics; human labor; liability; material resistance; inspection.

HOUSE-COMP-000 — TEST
Take one actually fabricated architectural component; recover every representational state between initiating request and final material object; record INPUT, INTERPRETER, REPRESENTATION, OPERATION, OUTPUT, HUMAN INTERVENTION, UNRESOLVED AMBIGUITY.

HOUSE-COMP-001 — QUESTION
Is SHRDLU an early prototype of the architecture required by “The House That Words Built”—not because it builds houses, but because it demonstrates ordinary sentence → interpreted intention → procedure → altered world?

HOUSE-COMP-001 — MISSING
Open-ended objects; unknown affordances; material tolerances; unmodeled consequences; multiple agents; conflicting goals; physical uncertainty; legal authority; irreversible failure.

HOUSE-COMP-001 — TEST
Hold a command constant while progressively expanding the world ontology; measure which categories, assumptions, procedures, and repair mechanisms must be added before the same sentence remains executable.

HOUSE-COMP-002 — QUESTION
Does “The House That Words Built” concern words that machines execute or words through which people become obligated to act?

HOUSE-COMP-002 — MISSING
The connection between commitment structures and physical representations: who translates promise into schedule, drawing, procurement, machine command, inspection?

HOUSE-COMP-002 — TEST
Trace one architectural change request through REQUEST → ACCEPTANCE → MODEL REVISION → DRAWING → PROCUREMENT → SITE WORK → INSPECTION; locate where social performativity ends and computational execution begins.

HOUSE-COMP-003 — QUESTION

HOUSE-COMP-003 — MISSING

HOUSE-COMP-003 — TEST
Compare the ontology of BDS with a contemporary BIM schema; identify which categories were added before increasingly downstream construction operations became computable.

HOUSE-COMP-004 — QUESTION

HOUSE-COMP-004 — TEST

HOUSE-COMP-005 — QUESTION

HOUSE-COMP-005 — TEST

HOUSE-COMP-006 — QUESTION

HOUSE-COMP-006 — MISSING

HOUSE-COMP-006 — TEST

HOUSE-COMP-009 — TEST

HOUSE-LANG-001 — QUESTION
Would “The House That Words Built” be more interesting if treated as a deliberate inversion of Heidegger rather than an extension of him?

HOUSE-LANG-001 — MISSING
A mechanism that moves from linguistic disclosure or preservation to physical production.

HOUSE-LANG-001 — TEST
Compare the operative verbs attached to language across Heidegger’s “Letter on Humanism,” “Language,” and “Building Dwelling Thinking”; code them as DISCLOSE, PRESERVE, DWELL, COMMAND, SPECIFY, CAUSE, CONSTRUCT.

HOUSE-LANG-002 — QUESTION
Before asking whether words can build a house, do we first need to ask what kind of activity “building” names?

HOUSE-LANG-002 — MISSING
The difference between ERECTING, DESIGNING, SPECIFYING, COORDINATING, MAINTAINING, INHABITING, CULTIVATING.

HOUSE-LANG-002 — TEST
Take one actual house project and classify events under DESIGN, SPECIFY, PROCURE, ERECT, ADAPT, MAINTAIN, INHABIT, CARE; ask which operations can actually be performed or reorganized by language.

HOUSE-LANG-003 — QUESTION
What changes if the fundamental object is not the house of language but the city of language through which houses are added, inherited, renovated, standardized, and abandoned?

HOUSE-LANG-003 — MISSING
Who modifies the city? What persists when a practice becomes obsolete? What corresponds architecturally to a new suburb of language?

HOUSE-LANG-003 — TEST
Trace the historical entry of vocabulary required to describe one contemporary house and ask whether the resulting house is produced by one language or by historically incompatible linguistic districts.

HOUSE-LANG-004 — QUESTION
Is “The House That Words Built” actually about language becoming material—or about language gaining control over the lineament layer from which material work is subsequently organized?

HOUSE-LANG-004 — MISSING

HOUSE-LANG-004 — TEST
Compare verbal description → sketch → measured drawing → BIM object → shop drawing → layout marks → constructed element for one stair, roof edge, window, or wall.

HOUSE-LANG-005 — QUESTION
What are the architectural felicity conditions under which a description can cease to be merely descriptive and become an instruction with consequences for a building?

HOUSE-LANG-005 — MISSING
Who recognizes the instruction? Who has authority? What representation receives it? What tolerance governs interpretation? Who bears responsibility?

HOUSE-LANG-005 — TEST
Keep “Move this wall 300 mm east” constant across casual conversation, sketch note, signed change order, BIM revision, and robotic command; observe which surrounding conditions determine whether anything happens.

HOUSE-LANG-006 — QUESTION

HOUSE-LANG-007 — QUESTION

HOUSE-LANG-007 — TEST

HOUSE-LANG-008 — QUESTION
Is LANGUAGE actually the research object, or is the more precise object SYMBOLIC OPERABILITY ACROSS HETEROGENEOUS REPRESENTATIONS?

HOUSE-LANG-008 — TEST

INGOLD-COMP-001 — TEST

INGOLD-COMP-002 — TEST

INGOLD-COMP-004 — TEST

INGOLD-PROMPT-001 — QUESTION
Which constraints are merely deferred because the user has not stated them yet, and which constraints are impossible to formulate until an artifact has actually been produced?

INGOLD-PROMPT-001 — MISSING
A distinction among UNSTATED CONSTRAINT, UNKNOWN CONSTRAINT, UNKNOWABLE-BEFORE-EXECUTION CONSTRAINT, EMERGENT POSSIBILITY.

INGOLD-PROMPT-001 — TEST
Take ten prompt-programming iterations and classify each new constraint as A known-before-generation but omitted, B discovered by seeing artifact, C created by a possibility the artifact introduced, D unresolved. If C exists, deferred formalization is not merely delayed specification.

INGOLD-PROMPT-002 — QUESTION
When a generated artifact changes the next prompt, how do we tell whether it has exposed an ERROR or created a POSSIBILITY?

INGOLD-PROMPT-002 — MISSING
A vocabulary for positive surprises: UNEXPECTED PROPERTY WORTH KEEPING; NEW POSSIBILITY CREATED BY OUTPUT; GOAL CHANGED BECAUSE OF ARTIFACT.

INGOLD-PROMPT-002 — TEST
Collect twenty prompt revisions and code whether SOMETHING WAS WRONG or SOMETHING INTERESTING APPEARED; separate FAILURE-DRIVEN from SURPRISE-DRIVEN revision.

INGOLD-PROMPT-003 — QUESTION
Where is the information that makes an underspecified prompt executable?

INGOLD-PROMPT-003 — MISSING
A method to distinguish USER-SUPPLIED CONSTRAINT, MODEL-INFERRED CONSTRAINT, PLATFORM DEFAULT, TRAINING-INDUCED CONVENTION, TOOL-IMPOSED CONSTRAINT.

INGOLD-PROMPT-003 — TEST
Give the same short prompt to models with substantially different priors or tool environments; keep wording constant and record unstated constraints each system supplies.

INGOLD-PROMPT-004 — QUESTION
Is deferred formalization fundamentally a programming phenomenon, or one instance of the older logic of skilled inquiry through making?

INGOLD-PROMPT-004 — MISSING
A taxonomy of artifact responses beyond PASS/FAIL: FAILURE, SURPRISE, AFFORDANCE, AMBIGUITY, SIDE EFFECT, NEW POSSIBILITY, LATENT DEFECT.

INGOLD-PROMPT-004 — TEST
Take fifty prompt iterations and classify why the next prompt changed: failure, possibility, ambiguity, affordance, nothing new. Test whether “failure becomes specification” covers most informative iterations.

INGOLD-PROMPT-005 — QUESTION
Does iterative prompting asymptotically approach a complete program, or does it produce better resources for situated generation while leaving an irreducible interpretive remainder?

INGOLD-PROMPT-005 — MISSING
Evidence showing whether repeated prompting actually reduces degrees of interpretive freedom; a thick prompt may accumulate constraints while the system supplies unstated judgement.

INGOLD-PROMPT-005 — TEST
Take a mature thick prompt across deliberately altered circumstances; measure what remains invariant, requires interpretation, breaks, and needs new constraints; repeat until behavior is determined or situated judgement continues.

INGOLD-PROMPT-006 — QUESTION
Should a programming system store constraints as propositions or as histories of tested encounters?

INGOLD-PROMPT-006 — MISSING
A criterion for deciding how much genealogy matters operationally; preserving every event is unusable, so compression must retain causal relevance without collapsing history into bare propositions.

INGOLD-PROMPT-006 — TEST
Take ten mature constraints; create FINAL PROPOSITION ONLY versus PROPOSITION + FAILURE + TEST + CORRECTION HISTORY; give both to a new agent modifying the artifact and measure regression prevention.

INGOLD-PROMPT-007 — QUESTION
Is failure legibility a property of the artifact, or of the artifact-plus-test-environment?

INGOLD-PROMPT-007 — MISSING
A taxonomy of FAILURE ACCESSIBILITY: directly legible; legible after interaction; after simulation; only with instrumentation; only after long duration; not reliably legible.

INGOLD-PROMPT-007 — TEST
Take twenty natural-language programming tasks; for every important failure record the environment needed to make it observable: screen inspection, interaction, unit test, simulation, adversarial input, physical test, longitudinal use, formal proof. Correlate success with test availability.

INGOLD-PROMPT-008 — QUESTION
Is deferred formalization a genuinely new unit of programming, or the computational recovery of an older unit of making in which conception and execution were never fully separated?

INGOLD-PROMPT-008 — MISSING
A historical comparison among craft production, interactive programming, REPLs, debugging, live coding, programming by demonstration, CAD iteration, LLM prompting. Novelty must be split among LOOP, SPEED, ACCESSIBILITY, and SEMANTIC LATITUDE.

INGOLD-PROMPT-008 — TEST
Historicize the loop. For each candidate practice record PARTIAL SPECIFICATION, EARLY EXECUTION, VISIBLE ARTIFACT, REVISION FROM OUTPUT, PRESERVATION OF PRIOR CONSTRAINTS, CHEAP REGENERATION, SEMANTICALLY LOOSE INPUT. Whatever remains after subtraction is the genuinely new property.
