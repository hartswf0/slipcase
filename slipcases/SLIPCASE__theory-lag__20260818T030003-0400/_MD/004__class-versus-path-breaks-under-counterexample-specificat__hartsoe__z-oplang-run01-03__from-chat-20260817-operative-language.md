TITLE:
Class versus path breaks under counterexample; specification, realization, and judgment survive.

SOURCE:

PASSAGE:
[PARAPHRASE]
The manuscript distinguishes path specifications, which prescribe sequences, from class specifications, which establish properties acceptable outcomes should satisfy. It suggests generative prompting may increasingly allow writers to author classes while delegating paths.

RESEARCH OBJECT:
A replacement for the class/path binary:

<SPECIFY>
→ <REALIZE>
→ <JUDGE>

These operations can be separated and distributed independently of whether the governing specification describes a class or a path.

LOCAL MOVE:
The source searches for a formal distinction capable of describing the changed object of generative authorship.

SOURCE TERMS:
“class”
“path”
“possibility space”
“acceptable outcomes”
“sequence of operations”
“author the class”
“delegating portions of the path”

WHAT BECAME STRANGE:
The apparent code/prompt distinction collapses.

SQL, CSS, tests, constraints, and declarative systems can specify acceptable conditions without providing an execution path.

Prompts can explicitly prescribe paths.

The more consequential separation appears elsewhere: who specifies criteria, who realizes one candidate, and who judges whether the realization satisfies the criterion.

QUESTION:
Does generative authorship become distinctive when specification, realization, and judgment cease to be obligatorily performed by the same agent?

DEEPER QUESTION:
Which of these operations must remain coupled for an artifact to remain recognizably authored rather than merely accepted?

MECHANISM:
<human>
[specifies] <criteria-or-procedure>.

<model>
[realizes] <candidate>.

<human>
[judges] <candidate against criterion>.

<judgment>
[modifies] <next specification>.

The resulting process distributes operations formerly collapsed into “writing.”

FORMAL SHIFT:
<CLASS / PATH SPECIFICATION>
→ <PRODUCTION PROCESS>
→ [DECOMPOSE BY OPERATION]
→ <SPECIFICATION / REALIZATION / JUDGMENT>

SOURCE FORMALISM:
The source explicitly supplies the conceptual distinction:

PATH SPECIFICATION:
“what sequence of operations to perform.”

CLASS SPECIFICATION:
“what kind of resulting object should count.”

No mathematical formalism is supplied.

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]

Production cycle:

S_t → R_t → J_t → S_(t+1)

where:
S = specification,
R = realization,
J = judgment.

Different agents may perform each morphism.

The research variable becomes the allocation:

A(S), A(R), A(J)

rather than merely whether S is class-like or path-like.

TENSION:
Class/path remains useful inside specification itself.

The new decomposition should not erase it.

A specification can still be:
- class-heavy,
- path-heavy,
- mixed.

The new claim is therefore orthogonal rather than substitutive.

MISSING:
Cases in which:
- machine specifies and human realizes,
- human specifies and machine judges,
- machine performs all three,
- multiple humans divide them.

These would reveal whether the triad describes prompting specifically or delegated production generally.

BOUNDARY:
The source supports class/path as a candidate distinction.

It does not itself make the specify/realize/judge distinction.

That is an inference generated by counterexamples to the stronger claim that programs specify paths while prompts specify classes.

TEST:
Take one intended artifact and create four workflows:

A. human specifies + human realizes + human judges,
B. human specifies + model realizes + human judges,
C. human supplies only examples + model infers specification + realizes + human judges,
D. model proposes specification + model realizes + human judges.

Compare where participants report authorship, control, surprise, and responsibility.
