TITLE:
Prompt engineering can be game construction rather than string elaboration

SOURCE:
Ludwig Wittgenstein, Philosophical Investigations, 4th ed., 1953/2009, §§2, 7.

SOURCE URL:
https://plato.stanford.edu/entries/wittgenstein/

PASSAGE:
[OUR INFERENCE FROM SOURCE]\nIf the activity already fixes roles, objects, permissions, and expected continuations, the utterance itself can remain short.

RESEARCH OBJECT:
[OUR INFERENCE]\nBETTER PROMPTING MAY REQUIRE BUILDING THE CONDITIONS OF USE, NOT WRITING MORE WORDS.

LOCAL MOVE:
Reframe prompt engineering as interface and world design.

SOURCE TERMS:
game construction; state; role; permission; ontology

WHAT BECAME STRANGE:
Long prompts often compensate for missing structure but cannot reliably replace it.

QUESTION:
Which prompt failures should be repaired in the surrounding game rather than in the prose?

DEEPER QUESTION:
Can prompt quality be measured partly by how much structure moves out of repeated language and into inspectable state?

MECHANISM:
External state and enforced rules reduce the burden placed on natural-language specification.

FORMAL SHIFT:
MORE_TEXT is not necessarily MORE_CONTROL.

SOURCE FORMALISM:
[NO SOURCE FORMALISM]

OUR FORMALIZATION:
CONTROL = f(game structure, state visibility, enforcement, test), not f(token count) alone.

TENSION:
Moving structure out of language may reduce flexibility and exploratory discovery.

MISSING:
Design patterns for deciding which constraints belong in prose, schema, direct manipulation, or runtime enforcement.

BOUNDARY:
This is a Hartsoe inference from the builder's game, not a claim made by Wittgenstein.

CITATION TRAIL:
Slab! -> operative thickness -> game construction -> thick prompting.

TEST:
Rewrite a long prompt as a short move inside a stateful interface; compare reliability and edit cost.

PLATFORM:
Prompt engineering; HCI; language games
