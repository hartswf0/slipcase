TITLE:
Operation Describe requires a return path from result to description

SOURCE:

PASSAGE:
[OUR SYNTHESIS]\nWithout a return path, any generated result can be narrated after the fact as satisfying the description.

RESEARCH OBJECT:
[OUR INFERENCE]\nDESCRIPTION -> INTERPRETATION -> WORLD/ARTIFACT -> EVIDENCE -> REVISION.

LOCAL MOVE:
Turn operative ekphrasis from a one-way 'words become things' story into an inspectable correspondence loop.

SOURCE TERMS:
Operation Describe; evidence; revision; return path; correspondence

WHAT BECAME STRANGE:
Execution alone is not enough; inspectability is what prevents retrospective storytelling from masquerading as control.

QUESTION:
What evidence does the resulting world return to the description that produced it?

DEEPER QUESTION:
Which interfaces make the correction loop visible rather than silently regenerating?

MECHANISM:
A declared relation is instantiated, exposed, compared with evidence, and revised.

FORMAL SHIFT:
D_n -> I -> W_n -> E_n -> D_(n+1).

SOURCE FORMALISM:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]

OUR FORMALIZATION:
Operativity becomes method when the world can contradict the description.

TENSION:
Some artistic practices intentionally resist fixed compliance criteria.

MISSING:

BOUNDARY:
Operation Describe is a Hartsoe research construct illustrated by the paper's cases.

CITATION TRAIL:
operative ekphrasis -> inspectable result -> evidence -> revision.

TEST:
Require a pre-generation called shot, preserve intermediate states, and record whether revision follows observed mismatch.
