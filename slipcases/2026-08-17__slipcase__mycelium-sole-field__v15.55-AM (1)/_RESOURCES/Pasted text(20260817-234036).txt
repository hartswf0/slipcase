<laws>
  1. ONE ZETTEL = ONE immutable payload = ONE root .txt file.

  2. _MD/ contains the same-named exact Markdown mirror.

  3. TXT IS HUMAN-PRIMARY.
     The root is immediately readable in an ordinary file browser.

  4. ZETTEL FILES CONTAIN THE EXACT PAYLOAD.
     Do not insert compiler metadata into them.

  5. Preserve ORIGINAL ID exactly.
     Never trust it as globally unique.

  6. Exact payload SHA-256 is machine identity when computable.

  7. Preserve every:
       appearance;
       SOURCE URL;
       source;
       BibTeX block;
       resource;
       consequential prompt.

  8. Every newly created zettel includes SOURCE URL.
     Never alter an old payload merely to add one.

  9. Compile every:
       PLATFORM entry;
       LINKS entry;
       [[WIKILINK]] anywhere in the payload.

  10. Distinguish:
        ZETTEL
        PLATFORM
        CONCEPT
        GHOST
        RESOURCE
        SOURCE
        PROMPT

  11. An unresolved intellectual address becomes a GHOST.
      Never guess merely to close the graph.

  12. Backlinks, MOCs, arrangements, maps, readers, cards, and papers
      are derived views. Never rewrite zettels to create them.

  13. Missing, ambiguous, conflicting, unresolved, and broken
      are valid archival states.

  14. Never invent:
        provenance;
        authors;
        dates;
        citations;
        URLs;
        DOIs;
        page numbers;
        graph targets;
        counts;
        hashes;
        findings.

  15. Never claim more context, verification, or human review
      than actually occurred.

  16. Every count, hash, graph statistic, PDF status, and ZIP status
      is computed with tools or marked PENDING / UNVERIFIED.
</laws>

<paper>

<adapt>
  FOREIGN SCHEMA:
    preserve foreign fields.
    Any [[...]] remains an address.

  THIN ZETTEL:
    missing ID/source/links does not disqualify it.

  PARTIAL CONTEXT:
    capture what exists and declare the boundary.

  SCALE:
    small collection → show everything;
    large collection → search and pagination;
    phone graph → neighborhood first.

  MERGE:
    merge exact payload identity only.

    Never merge merely by:
      filename
      title
      display number
      evocative name
      original ID
      citekey

    Preserve all appearances, ghosts, ambiguities, and conflicts.
    Rerun resolution after merge.

  UNLISTED CASE:
    prefer preservation over deletion;
    visible uncertainty over invented certainty.
</adapt>
