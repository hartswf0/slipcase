TITLE: If an instrument that never concludes still slows the operator, then latency is a route change and deliberation time is the common currency of both substrates

SOURCE: PROGRAMS/uam.json <Purpose> (an instrument whose product is a suspended judgment); read against the compute component identified in [[FORAGE-PT-029]]

PASSAGE: [QUOTE] uam.json: "<paper> [must-model] <philosophical conflict> where <philosophical conflict> := <use> [claims-to-explain] <meaning>" [PARAPHRASE] The instrument's output is not a reading but an objection that must be ruled on, which delays the operator without redirecting them.

RESEARCH OBJECT: Delay as a measurable effect of a description that changes no destination. The parent asked whether hesitation counts as routing. If it does, then the smallest unit of operative effect is not a redirected action but a lengthened deliberation — and that unit is measurable on both a human operator (response latency) and a machine one (tokens or passes before commitment).

LOCAL MOVE: This child converts the parent's rhetorical question into a shared quantity by noticing that the machine-side finding about compute time and the human-side phenomenon of hesitation are the same variable.

SOURCE TERMS: philosophical conflict / claims-to-explain / suspended judgment / operator ruling / hesitation

WHAT BECAME STRANGE: Every measure in the corpus records *which* action followed a description. None records *how long* it took. Yet the two substrates the corpus insists on unifying — human interfaces and machine prompts — both have a time-to-commit, and it is the only quantity that is natively comparable across them without analogy.

QUESTION: Does introducing an unresolvable objection lengthen time-to-commitment while leaving the eventual decision distribution unchanged?

DEEPER QUESTION: If a description can buy deliberation without changing the outcome, then some descriptions are purely temporal operators — and their value is entirely in what the delay itself produces, which is exactly the argument for friction in interface design and for extended computation in models.

MECHANISM: <DESCRIPTION CONTAINING AN UNRESOLVABLE OBJECTION> -> [OPERATOR CANNOT PROCEED WITHOUT RULING] -> additional deliberation -> [RULING] -> action, possibly identical to the no-objection case -> <SAME DESTINATION, LONGER PATH>

FORMAL SHIFT: <DESCRIPTION> -> <TIME-TO-COMMIT> -> [MEASURE LATENCY, NOT ONLY OUTCOME] -> <PURELY TEMPORAL OPERATIVE EFFECT>

SOURCE FORMALISM: NONE.

OUR FORMALIZATION: [OUR FORMALIZATION — NOT SOURCE SYNTAX] Two effects per description D: outcome shift, measured as a distance between action distributions; latency shift, measured as change in time-to-commit (seconds for humans, tokens or passes for models). A description with zero outcome shift and positive latency shift is a *temporal operator* — a category the corpus has no name for and which its outcome-only measures score as inert.

TENSION: READING A: delay is a real effect and friction that improves decisions is the whole design case for it. READING B: delay without outcome change is cost, not routing; calling it operative inflates the concept to cover anything that occupies attention, which is the boundary problem the corpus most needs to avoid.

MISSING: Any latency measurement anywhere in the corpus. Any evidence that induced deliberation improves the eventual decision rather than merely postponing it.

BOUNDARY: This proposes a quantity. It does not show that any instrument in the corpus produces delay, since none has been deployed and timed.

CITATION TRAIL: [[FORAGE-PT-004]] and [[FORAGE-PT-029]] -> the shared time variable -> next: friction and speed-bump studies in interface design, and adaptive-computation work where deliberation is allocated explicitly; both measure latency as an outcome rather than a cost.

TEST: One decision task, two conditions differing only by the presence of an unresolvable objection in the framing. Record both the decision distribution and time-to-commit, for human participants and for a model. A latency shift with no outcome shift instantiates the temporal operator.
