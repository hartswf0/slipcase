OPEN EDGES — ONTOLOGY CHECKPOINT

1. Find a principled stopping rule for prompt boundaries, or show why none is needed.
2. Test prompt identity across model/runtime transplantation.
3. Separate prompt efficacy from causal understanding: can an edit work for the wrong reason?
4. Find cases where visible prompt identity strongly predicts behavioral invariance despite runtime changes; these threaten the boundedness–causality dilemma.
5. Study methods sections in prompt papers: what exactly do authors publish when they say “we used the following prompt”?
6. Compare prompt taxonomies with runtime traces. Which taxonomic features retain effects after transformed context is held fixed?
7. Investigate whether “prompt” functions as a boundary object across HCI, NLP, software engineering, creative practice, and ML optimization rather than as one technical kind.
8. Distinguish authorship, causal control, responsibility, and provenance in rewritten/compiled prompt pipelines.
9. Test Suchman crossing against opposition: where does model conditioning make prompt-as-plan analogy fail decisively?
10. Historicize the term “prompt” itself: command-line prompt, theatrical cue, psychological prompt, instruction, prompting in ML. Does the current ontology inherit multiple incompatible genealogies?
11. Investigate the interface effect: does visual adjacency of prompt and output measurably bias human causal attribution?
12. Build a “prompt transplant” benchmark where the same inscription is moved across system prompts, model versions, tools, and context assemblers.
13. Develop invariants rather than total objects: what properties of an instruction survive changes of execution ecology?
14. Ask whether “operational language” should name a relation rather than a kind of text.
15. Pressure the final aphorism: is “the part of the cause we can see” too strong where prompt text is experimentally manipulated? Could “the part of control we can most easily see” be more accurate?
