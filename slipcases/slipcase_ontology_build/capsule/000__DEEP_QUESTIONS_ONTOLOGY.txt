DEEP QUESTIONS — THE VANISHING PROMPT

Q01. What kind of thing is a prompt if making it causally adequate makes it cease to be a prompt?

Q02. What are the identity conditions of a prompt across changes in model, system instruction, role hierarchy, retrieval, tools, tokenizer, stochastic state, and selection?

Q03. Is “prompt” a natural technical kind, a family-resemblance category, an interface convention, or a retrospective attribution of causality?

Q04. What is the minimum common ontology shared by a natural-language prompt, a role-message bundle, a generated prompt, a soft prompt, and a compiled context—if any?

Q05. If the only common property is “conditions a model,” what principled boundary excludes retrieved documents, tool schemas, model state, and random initial conditions from the category?

Q06. Can a prompt be a valid independent variable without being a sufficient causal unit? If so, which claims should be forbidden while that distinction remains unmarked?

Q07. What exactly is reproduced when a paper publishes its prompt: a string, an instruction, an experimental treatment, a probability distribution, or a historical situation?

Q08. When scholars say “the model followed the prompt,” what evidence distinguishes prospective causal control from retrospective fit between instruction and outcome?

Q09. Where does prompt meaning happen: in discourse, tokenization, embedding geometry, model activations, a temporal generation trajectory, or only in relations among all of them?

Q10. Is omission part of prompt operation when unstated requirements are supplied by model defaults? If so, where is the boundary between a prompt and what the model brings to it?

Q11. Is explicitness a linguistic property or a causal property? What should we call an instruction that is explicit in text but causally inert?

Q12. If a system silently rewrites a prompt, which object should appear in the Methods section as “the prompt”?

Q13. If two visible prompts compile to the same executed representation, are they different prompts experimentally but the same prompt operationally?

Q14. If one visible prompt compiles differently across executions, is it one prompt or many?

Q15. Can prompt version control exist without execution version control, or does that merely preserve one layer of a changing intervention?

Q16. Does context engineering solve prompt ontology, or does it reveal that the object cannot be stabilized below the level of a situated system state?

Q17. What evidence would falsify the boundedness–causality dilemma by showing a stable intermediate unit with both portable identity and high causal coverage?

Q18. How much of prompt scholarship’s certainty is produced by interface design—the visual adjacency of instruction and output—rather than by causal localization?

Q19. Does the term “prompt engineering” conceal several different practices: writing, configuring, conditioning, assembling, selecting, and experimenting?

Q20. What would be lost if scholarship used “prompt text” only for the inscription and refused to use “prompt” as an unqualified causal noun?

Q21. Does a prompt have meaning before a model receives it, or only ordinary linguistic meaning that becomes a different kind of operational meaning in relation to a model?

Q22. Can a model “understand” an instruction that is operationally effective but humanly meaningless? Can a humanly meaningful instruction be operationally empty? What ontology survives both cases?

Q23. When a concept is represented early and extinguished later, did the prompt succeed, fail, or change status through time?

Q24. What does weak prompting leave behind: absence, freedom, model prior, random-state affordance, or an invitation for another control channel to dominate?

Q25. Is the prompt the cause, a cause, a constraint, a resource, a trace, an address, a handle, or an alibi? Which of these roles are compatible, and which are being silently collapsed?
