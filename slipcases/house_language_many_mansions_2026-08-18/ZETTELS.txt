TITLE:
THE HOUSE THAT WORDS BUILT IS NOT A CLAIM ABOUT MAGIC WORDS; IT IS A QUESTION ABOUT WHETHER THE CHAIN FROM SENTENCE TO MATTER CAN BE COMPUTATIONALLY CLOSED.

SOURCE:
Terry Winograd — Procedures as a Representation for Data in a Computer Program for Understanding Natural Language — 1971; Charles Eastman et al. — An Outline of the Building Description System — 1974; Charles Eastman and Max Henrion — “GLIDE: A Language for Design Information Systems” — 1977; APT documentation.

PASSAGE:
NONE

RESEARCH OBJECT:
THE COMPILATION CHAIN FROM SENTENCE TO WALL.

LOCAL MOVE:
Across these systems, different portions of a formerly human interpretive chain become explicit computational objects: natural-language command, computable building description, design language, and machine-control language.

SOURCE TERMS:
normal English dialog; commands; building description; design information system; APT; language statement; machining function; postprocessor

WHAT BECAME STRANGE:
“Words build houses” is too compressed. The technical object is WORD → INTERPRETATION → REPRESENTATION → OPERATION → MACHINE/HUMAN ACTION → MATERIAL CHANGE.

QUESTION:
At what point does a verbal description cease to be merely upstream of construction and become part of an executable construction system?

DEEPER QUESTION:
How many human acts of interpretation can be removed, formalized, or delegated between the sentence and the wall before DESCRIPTION becomes PROGRAM?

MECHANISM:
Successive representational layers constrain the next available operation; linguistic instructions become consequential through parsing, representation, validation, transformation, compilation, control, and action.

FORMAL SHIFT:
<DESIRED PHYSICAL CHANGE>
→ <LINGUISTIC / COMPUTATIONAL REPRESENTATION>
→ [COMPILE THROUGH OPERATIVE REPRESENTATIONS]
→ <MATERIAL CHANGE>

SOURCE FORMALISM:
No single source supplies the complete pipeline; the chain is reconstructed across heterogeneous systems.

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]
SENTENCE → SEMANTIC REPRESENTATION → DESIGN OBJECT → GEOMETRY → BUILDING MODEL → FABRICATION DESCRIPTION → MACHINE INSTRUCTION → TOOL MOTION → MATERIAL STATE. At every arrow ask: WHO INTERPRETS? WHAT IS LOST? WHAT MUST BECOME EXPLICIT? WHAT CAN FAIL?

TENSION:
Austinian performativity explains social action through convention; programming execution explains action through formal semantics and machinery; construction can contain both.

MISSING:
Building codes; structural reasoning; tolerance; procurement; construction sequencing; site uncertainty; robotics; human labor; liability; material resistance; inspection.

BOUNDARY:
The historical systems do not establish an uninterrupted natural-language-to-building pipeline. “The compilation chain from sentence to wall” is OUR synthesis.

CITATION TRAIL:
Ivan Sutherland — Sketchpad; Nicholas Negroponte — The Architecture Machine; Christopher Alexander et al. — A Pattern Language; Stiny and Gips; Mitchell; CAD/CAM; BIM; numerical control; robotics.

TEST:
Take one actually fabricated architectural component; recover every representational state between initiating request and final material object; record INPUT, INTERPRETER, REPRESENTATION, OPERATION, OUTPUT, HUMAN INTERVENTION, UNRESOLVED AMBIGUITY.
