TITLE:
MUTUAL PROGRAMMING TURNS THE PROGRAMMED WORLD INTO A PROGRAMMER

SOURCE:
Richard Brautigan — “All Watched Over by Machines of Loving Grace” — 1967 — The Communication Company, San Francisco.

SOURCE URL:
https://www.brautiganarchives.xyz/machines.html

PASSAGE:
[QUOTE] “mammals and computers / live together in mutually / programming harmony”

RESEARCH OBJECT:
Brautigan places a strange adjective beside programming: MUTUALLY.

Programming normally implies an asymmetry: PROGRAMMER → PROGRAMMED. Brautigan imagines A ⇄ B.

The environment is no longer merely something written in advance and imposed. Its participants alter one another.

LOCAL MOVE:
The poem uses “programming” not merely for computer instruction but for reciprocal ecological relation between mammals and computers.

SOURCE TERMS:
mutually
programming
harmony
mammals
computers
cybernetic
ecology

WHAT BECAME STRANGE:
If programming becomes reciprocal, then a program cannot be completely identified with an initial instruction. Its subsequent state is partly a history of encounters.

QUESTION:
What would “natural-language programming” mean if the user, model, generated artifact, and environment all alter one another over time?

DEEPER QUESTION:
Could the proper unit of programming be neither PROMPT nor LOOP but CORRESPONDENCE?

MECHANISM:
participant A acts
→ participant B responds
→ response modifies A’s subsequent action
→ A responds
→ relation develops longitudinally.

FORMAL SHIFT:
<PROGRAMMER → PROGRAMMED>
→ <PARTICIPANTS IN FEEDBACK>
→ [RECIPROCALLY ADAPT]
→ <CO-DEVELOPING SYSTEM>

SOURCE FORMALISM:
NONE

OUR FORMALIZATION:
[OUR FORMALIZATION — NOT SOURCE SYNTAX]

UNILATERAL:
A → B

CORRESPONDENCE:
Aₙ → Bₙ₊₁
Bₙ₊₁ → Aₙ₊₁
Aₙ₊₁ → Bₙ₊₂
...

PROGRAM = history of reciprocal state changes.

TENSION:
“Mutual programming” is poetic language, not a technical feedback architecture.

Reciprocity can also be falsely claimed. A surveillance system that continually adapts to inhabitants is technically responsive while remaining politically unilateral.

So: FEEDBACK ≠ MUTUALITY.

MISSING:
A criterion for genuine reciprocal programming. Who may change the rules, refuse participation, inspect state, alter objectives, withdraw, remember, and forget?

BOUNDARY:
Brautigan does not define an algorithm for mutual programming. The correspondence with Ingold is conceptual, not evidence of historical influence.

CITATION TRAIL:
Tim Ingold — Making.
Norbert Wiener — feedback.
Stafford Beer — viable regulation.
Lucy Suchman — situated action.

TEST:
Compare two inhabited computational houses.

HOUSE A: inhabitants may act only inside immutable machine rules.
HOUSE B: some machine rules can change in response to inhabitants, and inhabitants can inspect, resist, or modify those adaptations.

Determine which transformations would be necessary before “mutual programming” describes more than adaptive surveillance.
