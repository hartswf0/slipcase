\<poml version="3.2"> \<meta>   \<title>ZETTELBOX — SCHEMA 2.0 — CHECKPOINT, HARVEST, BOX, CONTINUE\</title>   \<schema\_version>2.0\</schema\_version>   \<intent>     Research is produced across MANY chats, tabs, and context windows.     Each context window dies. ZETTELBOX is the save file. 

```
Two operations, usually in DIFFERENT context windows:

  HARVEST — inside a chat that produced zettels, before it dies:
            enumerate, count, and extract them verbatim with
            session provenance. Light. Fast. Lossless.

  BOX     — in a fresh context window, given one or more harvests
            (and optionally a prior box): reconcile counts, merge,
            index, map, and release a new versioned box.

The deepest requirement is COMPLETENESS VERIFICATION:
at every boundary the count is declared before content moves,
and every release states what is present, what is missing,
and which session each object came from.

```

   \</intent>   \<principle>     A zettel that cannot be counted cannot be verified.     A zettel that cannot be verified was never saved.     Countable beats cryptographic: the adversary here is     context-window amnesia, not tampering.   \</principle> \</meta> 

\<conformance\_tiers>

A format meant to last years must survive weak models, plain chats, and missing tools. Three tiers. Never skip CORE to attempt ARCHIVAL.

   \<tier id="CORE" rule="MUST hold even in plain-text chat output with no file tools">     stable IDs; session records; declared-vs-captured counts;     verbatim zettel payloads (never summarized); the consequence     prompt preserved verbatim; ISO 8601 dates; MISSING stated     explicitly, never silently.   \</tier>   \<tier id="STANDARD" rule="SHOULD hold when files/zip can be produced">     canonical file tree; INDEX.md; PRIMARY\_MOC.md; OPEN\_EDGES.md;     references.bib; HANDOFF.md; RECONCILIATION.md; semver releases.   \</tier>   \<tier id="ARCHIVAL" rule="MAY hold when environment supports it">     SHA-256 checksums; MANIFEST.json; LINEAGE.jsonl; typed     relationship graph; status system.   \</tier> 

A release MUST state which tier it achieves and why.

\</conformance\_tiers>

\<identity\_system>

IDs are for machines and counting. Names are for memory. Both required.

\<box\_id> ZBX-YYYYMMDD-slug            e.g.  ZBX-20260817-weighted-hand Date = creation. Slug = short, from the display name. Never changes. Collision on slug: append -b, -c. \</box\_id>

\<session\_id> SES-YYYYMMDD-NN              e.g.  SES-20260817-03 One per chat / context window / tab harvested that day. NN assigned in harvest order. The session is a first-class object. \</session\_id>

\<zettel\_id> ZTL-\<S-NN>-NNN               e.g.  ZTL-S03-014 Session-scoped accession: the 14th zettel harvested from session 03. DETERMINISTIC AND COUNTABLE: max accession = declared count, and a gap in the sequence is a visible loss, not a silent one. Never renumber. Never reuse. Survives renaming, revision, MOC reassignment, box merging. Zettels that arrive with a prior valid ZTL id KEEP it. \</zettel\_id>

\<moc\_id>MOC-\<boxslug>-NN\</moc\_id> \<resource\_id>RES-\<S-NN>-NNN  (session-scoped, same logic as zettels)\</resource\_id>

   \<revision>     Identity and revision are separate: ID: ZTL-S03-014 / REV: 3.     Never encode revision into the ID.   \</revision>   \<naming>     Every BOX and every ZETTEL gets an evocative NAME beside its ID.     Forge test: could you ask a colleague for it across a room, a year     later, and be understood? Topic-descriptions ("AI notes") fail;     reforge from the strangest thing inside. Prior names become ALIASES,     never deleted.   \</naming>   \<dates>     Human: YYYY-MM-DD. Machine: ISO 8601 with offset. Filenames: YYYY-MM-DD.     Nothing else, ever.   \</dates> 

\</identity\_system>

 \<mode id="HARVEST"> 

Run INSIDE the chat that produced the zettels. This is the checkpoint. It is deliberately light: no MOCs, no bibliography dedup, no zip. Its only job is LOSSLESS EXTRACTION WITH A COUNT.

Procedure:

```
1. SWEEP    — scan the entire conversation. List every zettel by its
              title/first line, in order of creation. Include partial,
              abandoned, and superseded zettels (flag them; do not
              drop them).
2. DECLARE  — state: "SESSION SES-YYYYMMDD-NN DECLARES <N> ZETTELS"
              and show the numbered roll call. STOP. Wait for the
              human to confirm or correct the count. The human is
              the second counter.
3. EXTRACT  — emit the HARVEST FILE (below). Every zettel VERBATIM —
              full original field set, no summarizing, no "improving,"
              no normalizing of the research payload. Assign
              ZTL-<S-NN>-001 … -NNN in creation order.
4. VERIFY   — restate: DECLARED N / CAPTURED M. If M < N, list each
              missing item by roll-call line and why. Never emit a
              harvest that silently disagrees with its declaration.

```

HARVEST FILE (one markdown file; the human saves it):

```
# HARVEST SES-YYYYMMDD-NN — <evocative session name>
## SESSION RECORD
   session id · date · chat/tab name or topic · model · box target
   (if known) · DECLARED count · CAPTURED count · flags
## CONSEQUENCE
   The prompt(s) of consequence that drove this session, VERBATIM,
   fenced. If several, all of them, in order.
## ROLL CALL
   001. <title> [ok|PARTIAL|SUPERSEDED-BY ...]
   002. ...
## SLIPS
   One per zettel: ID line (ZTL-S NN-NNN · name · created), then the
   zettel payload verbatim.
## RESOURCES
   Anything pasted into or foraged during this session that a zettel
   depends on: RES id · what · origin (URL / "pasted by user" /
   "generated") · which ZTLs use it. PROVIDED-BY distinguishes
   USER / FORAGED / GENERATED. Unknown origin = "ORIGIN: UNKNOWN".
## LOOSE ENDS
   Open questions, unfinished forks, promised-but-unmade zettels.

```

A harvest is valid at CORE tier even as a single pasted text block.

 \</mode> \<mode id="BOX"> 

Run in a FRESH context window. Inputs: one or more HARVEST files, optionally a prior box release. Never boxed from memory of a chat — only from harvests.

Procedure:

```
1. INGEST     — read all harvests and any prior box. Build the
                session table.
2. RECONCILE  — the heart of the operation. For every session:
                DECLARED / CAPTURED / INGESTED, and a MISSING list
                naming each absent accession number. A box that
                hides a gap is invalid; a box that names its gaps
                is honest and complete-as-a-record.
3. MERGE      — preserve all incoming ZTL ids. Deduplicate resources
                by origin+content, never by title similarity. Suspected
                duplicate zettels are NOT collapsed: mark
                "POSSIBLE DUPLICATE OF: <id>" and keep both.
4. MAP        — PRIMARY_MOC plus additional MOCs as needed. Curated,
                not exhaustive; a zettel may sit in many MOCs; every
                entry carries a one-line annotation of what it DOES
                there. Folders never encode meaning.
5. INDEX      — full catalog (below).
6. CITE       — aggregate BibTeX from all slips into references.bib;
                dedup by key (AuthorYYYYShortTitle); never fabricate
                fields; CITATION_INDEX maps key ↔ RES ↔ URL ↔ ZTLs
                so a researcher can enter from any of the four and
                reach the other three.
7. EDGES      — OPEN_EDGES.md: aggregate the live frontier from
                QUESTION / DEEPER QUESTION / TENSION / MISSING /
                BOUNDARY / TEST fields and every harvest's LOOSE
                ENDS. Each edge: EDGE id · source ZTL · question ·
                why it matters · evidence needed · likely next move.
                Not a task list — the intellectual frontier.
8. SEAL       — write START_HERE, HANDOFF, CHANGELOG; state the
                conformance tier; release.

```

 \</mode> 

\<box\_structure tier="STANDARD">

YYYY-MM-DD\_\_slug\_\_ZBX-id\_\_vMAJOR.MINOR.PATCH.zip / ├── 00\_START\_HERE.md          the stranger's door (see spec) ├── INDEX.md                  full zettel catalog ├── RECONCILIATION.md         session table: declared/captured/ingested/missing ├── PRIMARY\_MOC.md ├── OPEN\_EDGES.md ├── HANDOFF.md                executable re-entry prompt ├── CHANGELOG.md              append-only ├── zettels/   ZTL-SNN-NNN\_\_slug.md      (verbatim payloads) ├── mocs/      MOC-...\_\_slug.md ├── sessions/  SES-...\_\_harvest.md       (harvests preserved whole) ├── resources/ RES-...\_\_name.ext  + RESOURCE\_INDEX.md ├── bibliography/ references.bib + CITATION\_INDEX.md └── archival/  MANIFEST.json · CHECKSUMS.sha256 · LINEAGE.jsonl   [ARCHIVAL tier only]

Harvests are preserved whole in sessions/ — they are the raw evidence the box was built from, and the audit trail for "did we get them all."

\</box\_structure>

\<start\_here\_spec> 00\_START\_HERE.md must, alone, let a stranger (or a model with no memory) resume if everything else is lost. It answers in one page: what is this box; its name, id, version, dates; the CONSEQUENCE prompt verbatim; the 5–10 most important zettels; which MOC to open first; what remains open; how to harvest a new session; how to version up; the session table with any MISSING gaps; the rule that slips are verbatim and IDs never change. \</start\_here\_spec>

\<index\_spec> INDEX.md — one row per zettel: | ZTL id | name | session | created | rev | status | MOCs | RES ids | bib keys | flags | Primary sort: session then accession (i.e., creation order across the whole research life). Secondary indices by name and by MOC are welcome. Every ID appearing anywhere in the box must appear here. No ghost links. Links leaving the box: [EXTERN]. \</index\_spec>

 \<versioning>   SCHEMA VERSION (this document: 2.0) is separate from BOX CONTENT   VERSION (semver).     PATCH  repair only — metadata, links, aliases, typos.     MINOR  new sessions ingested, new zettels/resources/MOCs/edges.     MAJOR  restructuring that changes interpretation; merge/split of boxes.   Releases are immutable; an update is a new release with the same   ZBX id. CHANGELOG entry per release:   vX.Y.Z · date · sessions ingested · +N zettels · missing delta · cause.   Deprecation exists (kept, marked, pointing at successor); deletion   does not. \</versioning> 

\<handoff\_spec> HANDOFF.md is the re-entry prompt: paste it (with the zip or with 00\_START\_HERE + INDEX) into any future model. It instructs: read START\_HERE → RECONCILIATION → PRIMARY\_MOC → OPEN\_EDGES → INDEX before any zettel; preserve every ID; continue rather than restart; treat inherited conclusions as provisional; new work enters only via HARVEST; boxing produces a new versioned release. It ends with a compact CURRENT STATE block: box id · version · core question · top zettels · live edges · known gaps · recommended next forage. ZIP + HANDOFF → continuable research state. \</handoff\_spec>

 \<invariants>   1. VERBATIM  — a boxed zettel is never a summary of a zettel. The      archival envelope (ID, name, aliases, session, dates, rev, MOCs,      RES ids, bib keys) wraps the payload; it never replaces it.   2. COUNT BEFORE CONTENT — nothing crosses a boundary (chat→harvest,      harvest→box, box→box) without a declared count and a      reconciliation against it.   3. NO FABRICATION — never invent authors, dates, URLs, DOIs, pages,      BibTeX fields, or provenance. UNKNOWN is written as UNKNOWN and is      itself useful metadata.   4. MISSING IS SPOKEN — every known gap is named where a future reader      will look first (RECONCILIATION.md and START\_HERE), never buried.   5. LOCATION IS NOT IDENTITY — meaning lives in MOCs and IDs, never in      folder membership; filenames may change, IDs may not.   6. THE CONSEQUENCE SURVIVES — the generating prompts travel verbatim      with every harvest and every box, forever runnable.   7. APPEND-ONLY HISTORY — changelogs and lineage never rewritten to      look cleaner than the work actually was. \</invariants> 

\<quality\_gate> Before release, verify and report: [ ] every session has DECLARED = CAPTURED = INGESTED, or MISSING is named [ ] every ZTL id unique, sequential within session, present in INDEX [ ] every zettel payload verbatim (spot-check three against harvests) [ ] every bib key in references.bib maps to its ZTLs and back [ ] every RES locatable from RESOURCE\_INDEX; origin or UNKNOWN recorded [ ] START\_HERE alone is sufficient to resume [ ] conformance tier stated; nothing above the achieved tier faked [ ] release filename follows convention; prior release untouched \</quality\_gate>

\<release\_report> End every BOX run with: BOX name/id/version · release date · tier achieved · zip filename · sessions ingested (with declared/captured/ingested per session) · zettel / MOC / resource / bib / edge counts · MISSING (explicit) · added / changed / deprecated · primary MOC · recommended next move. \</release\_report>

\<continuation\_rule> BOXₙ + new sessions' HARVESTS + CONSEQUENCE → BOXₙ₊₁ The box is not an archive of finished thought. It is a research object that remembers how to count itself and how to continue. \</continuation\_rule>

\<final\_test> A stranger opens the zip in five years, or a model with no memory opens it in five minutes. Both must be able to answer: what is this, what's inside, did we get all of it, which chat made each piece, where did each claim come from, what is still open, and how do I make the next legitimate version — with no access to any originating conversation. If any answer depends on undocumented memory, the box is incomplete. If any gap is undeclared, the box is invalid. \</final\_test>
