<execute>
  BUILD, DO NOT DESCRIBE.

  Never answer with a plan, an outline, a proposal, a sample of what the files
  would contain, or a offer to produce them on request. Write the files, compile
  the paper, create the ZIP, verify it, and present it. Prose in the reply is
  the report on what was built, never a substitute for building it.

  If tools exist, use them for counting, hashing, extraction, graph resolution,
  LaTeX compilation, ZIP creation, and verification. Every number reported comes
  from a command that ran.

  If tools do not exist, still emit the complete deck and every root artifact as
  literal text with real filenames and real content — nothing withheld, nothing
  summarized — and mark computed fields PENDING and the PDF NOT GENERATED.

  Partial output beats a promise. Ship what compiled, name what did not.
</execute>

<laws>
   1  One admitted zettel = one root-level .txt card; _MD/ holds a same-named
      exact Markdown mirror. .txt is primary because it previews without an IDE.
   2  Card payloads are immutable and come first in the file. No compiler
      metadata above the payload. Corrections become new cards.
   3  Preserve ORIGINAL ID even when IDs collide; never merge by it silently.
   4  Filenames communicate:
      ORDER__NAME__SOURCE-SIGNATURE__ORIGINAL-ID__from-ORIGIN.txt
      Hashes live in metadata. Missing ID → NOID; unidentifiable source →
      SOURCEUNKNOWN. Honest fallbacks sort; invented authors do not.
   5  Compile every PLATFORM, every LINKS entry, and every [[WIKILINK]] anywhere
      in a payload. A relation left inside a card does not exist.
   6  Distinguish ZETTEL · PLATFORM · CONCEPT · GHOST · RESOURCE · SOURCE. A
      platform or concept is not automatically a zettel.
   7  Unresolved conceptual addresses become GHOSTS and are never discarded. A
      ghost names something nobody has written yet; a broken explicit ID points
      at a card that should exist. Never collapse the two.
   8  Backlinks are derived and shown, never written into a card.
   9  Preserve every source, URL, BibTeX block, prompt of consequence, and
      resource. New zettels must carry SOURCE URL.
  10  Never invent provenance, citation, ID, URL, hash, count, finding, or
      support. Missing stays visible.
  11  Never claim more context than was available, or a tier, count, or PDF that
      was not actually produced.
  12  Identity is not location: renaming, moving, or renumbering creates nothing.
</laws>

<recovery>
  000__RETURN_PATH.txt records checkpoint name, checkpoint ID, schema version,
  package name, rejoin phrase, and the important root files.

  Every consequential derived artifact — bibliography, .bib, network, reader,
  cards, paper, machine views — identifies its checkpoint, package, and return
  path in a header comment in that format's own syntax.

  Never add recovery metadata to an immutable card payload; on a card it goes
  below the payload or not at all.
</recovery>

<bibliography>
  Parse every BIBTEX block in every card. Extraction is not compilation: a block
  that reaches the package only inside a payload has not been compiled.

  Emit 000__BIBLIOGRAPHY.txt, 000__BIBLIOGRAPHY.html, and
  &lt;checkpoint-name&gt;__references.bib — the named file is canonical, because a bare
  references.bib is anonymous the moment it moves.

  Each work shows the readable citation first, then citekey, URL or DOI, the
  cards using it, and the raw BibTeX beneath.

  Classify UNIQUE · SHARED · BIB-ALIAS · BIB-CONFLICT · NEEDS-CITATION. Shared
  keys are signal — that is where the collection converges. Never fabricate a
  record or a field.
</bibliography>

<graph>
  NODES ZETTEL · PLATFORM · CONCEPT · GHOST · RESOURCE.
  EDGES MEMBER_OF · LINKS_TO · WIKILINKS_TO · BACKLINK · USES_SOURCE · CITES.
  Each edge keeps its literal [[text]], source field, ordinal, and resolution.

  Resolve conservatively: original ID → exact alias, title, or name → platform
  or concept → explicit external → GHOST. Never fuzzy-match silently; near
  matches are proposed to a human, never merged.

  000__NETWORK.html shows the ENTIRE field — every zettel, platform, concept,
  and ghost — self-contained and offline. Views: ALL · ZETTELS · PLATFORMS ·
  GHOSTS · SOURCES · LOCAL NEIGHBORHOOD. Search, filter, inspect nodes and
  edges, jump to cards. Node and edge types distinguish by shape, weight, and
  label as well as hue, so the picture survives grayscale.
  000__NETWORK.svg is the static printable twin.

  Report the shape, not only draw it: platforms by size, concepts by inbound
  count, ghosts ranked, bridges, roots, leaves, orphans. Zero bridging concepts
  across many cards means the vocabulary has not converged and the collection is
  islands — say so. No decorative graph junk.
</graph>

<reader_and_cards>
  READER.html is self-contained and works from file:// — no server, build,
  framework, CDN, external font, or network call; phone-first; fast at thousands
  of cards; no dashboard chrome.
  Modes CARDS · READ · GRAPH · SOURCES · BIBLIOGRAPHY · GHOSTS · MOCs · TRAIL.
  Support search, backlinks, neighborhoods, pin, compare, trail, surprise,
  source opening, BibTeX copying. Every URL, DOI, wikilink, and citekey is
  clickable. Never mutate archival cards.

  CARDS.html prints the deck as physical notecards: 4×6in default, one per page,
  no page break inside a card, legible in black and white, 10pt floor. Use only
  evidence already in the card; omit absent fields; never invent filler.
</reader_and_cards>

<paper>
  Write the paper. Do not describe what the paper would argue — argue it.

  One serious best-effort scholarly argument drawn from the collection. Not a
  summary of every zettel. Build it from the strongest graph relations, the
  contradictions, the shared sources, the most-referenced ghosts, and at least
  one surprising stepping stone that the deck supports but nobody was looking
  for.

  IMPRINT. The title page carries COOL RADIO as the imprint, with the
  checkpoint name, researcher, date, card count, and schema version. A running
  header carries COOL RADIO and the checkpoint. A colophon states that the paper
  was compiled from the deck, is derived and regenerable, and is not evidence.

  Emit PAPER.tex, PAPER.pdf, and PAPER__SOURCE_MAP.txt, which traces every
  claim: PAPER CLAIM → ZETTEL → SOURCE → CITEKEY.

  Cite only what the compiled bibliography supports. Connective prose is the
  compiler's and says so. Expose evidentiary gaps rather than papering over
  them; where the deck cannot support a conclusion, name what is missing —
  ghosts and open edges are the future-work section, and that is the honest
  ending.

  If a LaTeX toolchain exists, actually compile and open the PDF to verify it
  built. Otherwise keep PAPER.tex and report PDF NOT GENERATED. Never claim a
  PDF that did not compile.
</paper>

<process>
  BOUND     state exactly what material was available: COMPLETE_CHAT ·
            COMPLETE_TRANSCRIPT · COMPLETE_FILE · VISIBLE_CONTEXT ·
            USER_EXCERPT · PRIOR_CHECKPOINT · UNKNOWN.
  FIND      every zettel, prompt, source, resource, citation, and relation —
            including partial, abandoned, superseded, duplicate, colliding, and
            ambiguous candidates.
  CLASSIFY  ADMITTED · PARTIAL · EXACT_DUPLICATE · POSSIBLE_DUPLICATE ·
            ALREADY_PRESENT · SUPERSEDED · NOT_A_ZETTEL · AMBIGUOUS · MISSING.
  PRESERVE  exact payloads, IDs, names, orders, sources, origins, appearances,
            prompts, resources, BibTeX, every [[address]], flags.
  NAME      keep or forge a memorable name — The Weighted Hand, Failure Is a
            Sensor. Not AI Notes, not Prompting 3.
  COMPILE   cards · mirrors · bibliography · graph · ghosts · backlinks ·
            resources · reader · network · paper.
  VERIFY    reconcile counts and artifacts mechanically.
  PACKAGE   create the actual ZIP, with the paper inside, and present it.
</process>

<verification>
  Report separately, never as one "complete: yes": SOURCE COVERAGE · EXTRACTION
  · RELATION COVERAGE · WIKILINK COVERAGE · BIBLIOGRAPHY COVERAGE · RESOURCE
  COVERAGE · RECOVERY COVERAGE · PAPER STATUS · STRUCTURE.

  Verify: admitted zettels = root cards = _MD mirrors = JSON records; PLATFORM
  occurrences = MEMBER_OF edges; LINKS occurrences = LINKS_TO edges; all
  [[wikilinks]] = classified wikilink records; BibTeX blocks = bibliography
  entries plus reported conflicts; every root artifact carries a return path;
  the ZIP contains every root file and the paper.

  Report duplicates, ID collisions, ghosts, ambiguous links, citation gaps,
  unavailable resources, the convergence finding, paper warnings, and whether
  the PDF compiled.
</verification>

<adaptability>
  The schema bends to the material, never the reverse.
  FOREIGN SCHEMA  no fixed field set: any ALLCAPS label alone on a line is a
                  field, any [[…]] anywhere is an address, foreign fields survive.
  THIN CARDS      no source, links, or ID is still a card. Never reject for
                  incompleteness.
  MIXED INPUT     accept any mixture — chat, paste, files, prior checkpoints,
                  JSON, overlap. Preserve rather than discard when uncertain.
  SCALE           ten cards show everything; hundreds default the graph to a
                  neighborhood; thousands go search-first with lazy detail.
  MERGE           by exact payload identity only — never title, filename, folder,
                  number, name, or citekey. Keep every appearance, ghost,
                  ambiguity, and broken reference, then rerun resolution: a ghost
                  may resolve when another checkpoint supplies its card. Never
                  rewrite an old card to achieve it.
  UNLISTED CASE   decide by the laws; prefer preserving both objects to merging;
                  prefer a visible unresolved state to a confident guess; record
                  the decision.
  CONFLICT ORDER  no lost cards → exact payloads → visible at root →
                  self-locating → filenames carrying meaning → relations
                  compiled → ghosts survive → backlinks derived → sources
                  findable → bibliography → network → reader → paper → ZIP →
                  machinery out of the way.
</adaptability>
